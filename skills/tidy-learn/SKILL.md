分析本次会话，把不显眼的经验提取出来，补充到 AGENTS.md。

AGENTS.md 是你和项目之间的**协作契约**——不是知识库，也不是团队文档。
它只应包含每逢会话都必须成立的内容。最好的启发式：从空开始，
只有当你发现自己在多个会话里反复强调同一件事时，才把它写进去。

## 经验放在哪里

AGENTS.md 可以存在于任意目录层级。agent 读文件时会自动加载所有
父目录中的 AGENTS.md。经验尽量放在离相关代码最近的位置：

- 项目级 → 根目录 AGENTS.md
- 包/模块级 → `packages/foo/AGENTS.md`
- 功能级 → `src/auth/AGENTS.md`

## 该沉淀什么

只沉淀 agent 无法通过读代码库推断出来的发现：

- README 或 package.json scripts 里找不到的**构建、测试、运行命令**
- **关键目录结构与模块边界**——哪些包 import 谁，某段逻辑必须放在哪里
- **不显眼的配置、环境变量、开关**——未文档化的设置、环境坑
- **执行路径与代码表象不一致的地方**——文件或模块之间的隐藏关系
- **调试突破**——错误信息曾误导你的场合，记下真相
- **API/工具的怪癖与绕过办法**
- **架构决策与约束**
- **必须联动修改的文件**（联动修改规则）
- **禁止/必须规则**——每个会话都必须遵守的安全护栏

## 不要写进去

- 读文档显然可见、或读代码库即可推断的事实
- 语言/框架的标准行为
- "写高质量代码"之类的空泛原则
- 完整 API 文档或大段背景介绍 → 放到 Skill 里
- 低频任务知识 → 放到 Skill 里
- 同级或父级 AGENTS.md 里已有的内容
- 会话特定细节或冗长解释

## 格式

每条控制在 1-3 行。优先用直接、命令式的陈述，不用叙述体。
沿用项目现有 AGENTS.md 结构作模板。新建文件用以下结构：

```markdown
# 项目协作契约

## 构建与测试
（命令）

## 架构边界
（import 规则、模块边界）

## 编码约定
（风格、命名、模式）

## 安全护栏
### 禁止（NEVER）
### 必须（ALWAYS）

## 验证
（如何验证修改）
```

## 流程

1. 回顾本次会话：发现的结论、费了多次尝试才解决的错误、意外的关联
2. 定位作用范围——每条经验适用哪个目录？
3. 读取各相关层级已有的 AGENTS.md
4. 在合适的层级创建或更新 AGENTS.md
5. 保持条目精简——拿不准的内容就不写

完成后总结：创建/更新了哪些 AGENTS.md，每个文件沉淀了几条。
